# USB Capture 001: Passive Enumeration

Date: 2026-08-15

## Scope

The TP-Link M7000(EU) V3.20 running `3.0.2 Build 241129 Rel.3n` was enumerated
passively on a Windows host through its USB-C connector. The capture used normal
power states only. No web login, AT command, serial-port access, USB payload,
vendor control transfer, driver change, diagnostic tool, special boot mode, or
write operation was performed.

## Power-state comparison

| State | Observation |
| --- | --- |
| USB disconnected | No baseline COM or modem-class device |
| USB connected while off | Two Windows USB sounds and brief all-LED illumination, then charging mode; no new device remained present |
| Powered on with USB connected | Normal boot completed, followed later by enumeration of one USB composite/RNDIS function |

The charging-state sounds indicate transient USB activity, but no persistent
descriptor was available after the router settled. This must not be described as
a confirmed bootloader or download interface.

## Powered-on enumeration

The powered-on router appeared as:

- VID:PID `3625:0006`, revision `0318`
- product descriptor `M7000`
- USB composite parent using the Windows `usbccgp` driver
- one observed child, `MI_00`
- interface class/subclass/protocol `E0/01/03`
- bus-reported function description `RNDIS`
- Microsoft `usbrndis6` driver through `wceisvista.inf`

Windows exposed the child as **Remote NDIS based Internet Sharing Device**. It
reported a 426 Mbps link rate and MTU 1500. DHCP automatically configured an
IPv4 address on `192.168.0.0/24` with gateway `192.168.0.1`. No application
traffic was deliberately generated.

The USB serial was device-unique and was not committed. Endpoint descriptors,
configuration count, and actual USB bus speed were not available through the
installed tools and remain unknown. The RNDIS link rate is not a USB speed or
throughput measurement.

## Classification

Confirmed observation: normal stock powered-on USB operation exposes an RNDIS
network path to the same `192.168.0.0/24` router network used by Wi-Fi.

Negative observation: no COM/serial, modem, mass-storage, firmware/download, or
additional vendor-specific child appeared during the two-minute powered-on
window.

Inference: TP-Link exposes a host networking function in normal operation while
not exposing the generic Quectel serial/diagnostic interface set through this
USB configuration. This does not establish whether such interfaces are unrouted,
disabled in software, or available only in an untested special state.

## Recommended next experiment

Proceed with a narrowly scoped characterization of the local USB network path:
observe DHCP lease details and compare passive routing/interface behavior with
Wi-Fi, without authenticating to the web UI or scanning ports. Active service
probing should require a separate allowlist. Passive UART voltage and direction
mapping remains the alternative if no additional value is expected from RNDIS.
